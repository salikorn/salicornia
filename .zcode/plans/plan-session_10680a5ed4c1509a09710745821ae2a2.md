# salikorn — test suite + GPU-trainer ms/step tuning + launch-parameter autotuner

Three coupled deliverables: (1) a real test suite (the ad-hoc gates inside spikes graduate into a
CTest-registered suite), (2) an optimization ladder for the GPU trainer's ms/step with the suite
as the safety net, and (3) an **autotuner utility** that searches the launch-parameter space
(tile/block sizes, group sizes, chunk widths, elements-per-thread) per kernel and shape class —
our kernels are runtime-compiled HLSL strings, so permutations are generated, gated, and timed
automatically, and the winners are loaded by the engine from a profile file.

## 1. Test framework — minimal, in-repo
`src/xlab/test.hpp` (~120 lines): self-registering tests via macro, `CHECK`/`REQUIRE` with value
printing, float compares (abs/rel/ULP), `SKIP_IF`, per-test ms timing, JSONL results into `runs/`
via the existing `xlab::Run` logger, non-zero exit on failure. No external dependency.

## 2. Test suite (`tests/`, CTest labels `unit` / `gpu` / `perf`)
- `test_fp16` (unit): fp16/bf16/fp8e4m3 ⇄ f32 round-trips (10M random + subnormals, ±Inf, NaN,
  over/underflow), known bit patterns.
- `test_safetensors` (unit): synthetic fixture write+read via mmap; real shard-62 header checks
  (351 tensors, known shapes) with SKIP_IF missing.
- `test_linalg` (unit): known-spectrum eigen recovery, square-Q exact-fold (SliceGPT theorem),
  exact-rank lossless truncation, orthonormalize idempotence, Gram vs Eigen direct.
- `test_gpu` (gpu, SKIP without a working adapter): GEMM NT/NN/TN vs CPU incl. element-offset
  addressing, syrk, elem kernels, packed Adam vs CPU, one-step trainer parity (AE and VQ modes —
  the graduated `--gate`), fast-mode vs conservative recording equivalence.
- `test_codecs` (unit): bake-off parser (finite/NaN), bpw arithmetic, int8 RTN.
- `test_autotune` (unit): permutation generator covers the declared space; candidate gating
  logic; profile JSON round-trip (read-back equals written winners).
- Runner `scripts/test.bat` → `ctest -L unit` (default), `-L gpu`, `-L perf`; README documents.

## 3. Baselines and structural perf ladder (one change per rung, gate + bench each)
Baselines to beat (batch 512, L=64): AE 8.8 ms/step, VQ-K256 23.0, VQ-K4096 123.3.
- T4a persistent staging ring: uploads/downloads recorded into the step's own command list, zero
  per-step `CreateCommittedResource`.
- T4b dataset-resident training: 40 MB train matrix lives on GPU; per-step upload shrinks to a
  2 KB index buffer + gather kernel.
- T4c fast-mode recording (resources stay SRV/UAV across the list, UAV barriers only between
  dependent dispatches) behind a flag, adopted only if parity + stability gates pass;
  conservative mode remains the fallback.
- T4d tiled `vq_nearest` (parallel distance reduction per patch — the 123 ms hot spot).
- T4e merged single-dispatch Adam over the packed state.

## 4. Autotuner utility (`tools/autotune.cpp`)
Because kernels are runtime-compiled HLSL strings, each launch parameter becomes a shader
`#define` substituted before `D3DCompile` — no offline toolchain.
- Search space: GEMM/syrk tile TS ∈ {8,16,32,64} × group size {64,128,256} × K-unroll {1,2,4} ×
  TDR chunk width {256,512,1024,2048}; elem kernels: group {64,128,256,512} × elements-per-thread
  {1,2,4,8}; vq_nearest: threads-per-patch {1,4,16,64} × K-tile {16,64,256}; CPU side: gram block
  size {128,256,512,1024} (one real constant in our code).
- Protocol per candidate: compile → **correctness gate vs CPU reference (mismatch/NaN ⇒
  disqualified — the tuner may never pick a broken variant)** → warmup + median-of-5 timings on
  the shape classes that matter (trainer shapes 512×384×256 etc., analysis shapes 4096² Gram,
  2048-col eigen GEMM). Full sweep results go to `runs/`; winners per (op, shape-class) to
  `profiles/best.json` plus a human-readable table artifact.
- Adoption: `src/gpu/kernels.hpp` gains a `KernelSet` that builds kernels from the profile
  (defaults = current hand-picked values when the file is absent), so tuned geometry loads at
  startup with zero code changes. CLI: `tools/autotune.exe --op all --out profiles/best.json`,
  `--quick` (pruned grid), `--only gemm_nt,vq_nearest`.
- Methodology notes logged honestly: shared-memory iGPU timing variance → median-of-5 with
  outlier discard, rerun-topped winners; sweep budget capped (~2k candidate-compiles) so a full
  sweep finishes in minutes.

## 5. Order and gates
T1 framework + unit green → T2 gpu green → T3 baselines → T4a–T4e structural rungs (parity gate
each) → T5 autotuner + full sweep + profile adoption (parity + bench again) → T6
`reports/e-perf.md`: the ladder, the tuned-vs-default deltas, gates re-run; targets AE ≤3 ms,
VQ-K256 ≤8 ms, VQ-K4096 ≤15 ms/step (targets honest, not hard CI thresholds — `perf` tests stay
non-blocking). Any rung that fails its gate reverts.

## Non-goals
No CI infra, no coverage tooling, no CPU-trainer tuning beyond the gram-block sweep, no changes
to model/codec math.
